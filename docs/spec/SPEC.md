# Spec: Atheleo (Flutter Android 리팩토링)

- 상태: 승인됨 (2026-11-09 최초 승인, 2026-11-13 설계 검토 반영 승인)
- 마지막 수정: 2026-11-13
- 근거 자료: 기존 저장소 `JJonyeok2/Atheleo`(React Native), Colab 노트북 "AI Model"(MoveNet, DTW 실험)

## 1. 목적

혼자 운동하는 사람이 휴대폰 카메라 하나로 푸쉬업, 스쿼트 횟수와 자세를 실시간으로 확인하고, 화면을 보지 않아도 음성으로 교정 안내를 받게 한다.
기존 앱은 매 프레임을 서버로 보내 분석해서 지연이 컸고, 화면 하나에 모든 로직이 몰려 유지보수가 어려웠다.
이번 리팩토링은 자세 추정을 기기 안으로 옮기고, 판정 로직을 테스트 가능한 단위로 분리하는 것이 핵심이다.

## 2. 사용자와 상황

| 사용자 | 상황 | 원하는 결과 |
|---|---|---|
| 홈트레이닝 초보자 | 거실에서 휴대폰을 세워 두고 운동 | 횟수를 대신 세 주고, 틀린 자세를 그 자리에서 알려 줌 |
| 운동 경험자 | 세트와 휴식 시간을 지켜 루틴 수행 | 목표 횟수, 세트, 휴식을 자동으로 관리 |
| 기록을 남기고 싶은 사용자 | 운동 후 결과 확인 | 날짜별 횟수, 점수, 자주 틀린 자세를 확인 |
| 개발자 본인 | 판정 모델 학습 데이터 수집 | 운동 중 랜드마크를 파일로 내보내기 |

## 4. 사용자 흐름

### 정상 흐름 (운동)

1. 앱 실행 → 홈에서 운동 종류(푸쉬업, 스쿼트) 선택
2. 카메라 권한 확인 → 촬영 가이드 화면(운동별 안내 문구, 거리 안내, 전신이 보이는 실루엣 표시)
   - 푸쉬업: "휴대폰을 옆에 세우고 측면에서 약 2m 이상 떨어져 주세요. 전신이 화면에 들어와야 해요." 준비 자세 안내 "엎드려 팔을 편 자세를 잡아 주세요"
   - 스쿼트: 측면에서 전신이 화면에 들어오는 거리 안내(거리 값은 Q-07), 준비 자세 안내 "옆으로 서 주세요"
   - 상태가 바뀔 때(전신이 안 보임, 자세 잡기, 유지) 음성으로도 안내한다.
3. 운동별 준비 조건(7장 자세 게이트 포함)이 2초 이상 안정적으로 유지되면 3·2·1 음성 카운트다운과 "시작" 안내 후 운동 화면으로 넘어간다. 이때 카메라와 감지 세션은 끊기지 않는다.
4. 운동 세션(촬영 가이드 진입부터 결과 화면 진입 전까지, 휴식 포함) 동안 화면이 꺼지지 않는다. 세션이 끝나면 화면 꺼짐 방지를 해제한다.
5. 반복할 때마다 횟수 음성 안내, 반복 종료 시 점수 표시와 섬광 색상
6. 자세 오류가 감지되면 해당 교정 문장 음성 안내(같은 문장은 5초 안에 다시 말하지 않음)
7. 목표 횟수 달성 → "세트 완료, N초 쉬세요" → 휴식 카운트다운(분석 중단) → 휴식 종료 3초 전 음성 안내 → "다음 세트를 시작하세요" → 분석기 초기화 후 다음 세트(측정 쪽 다시 결정, 반복 번호 1부터)
8. 마지막 세트 종료 또는 사용자가 종료 → 결과 화면(총 횟수, 평균 점수, 자주 나온 오류)
9. 결과는 로그인 여부와 관계없이 로컬 DB에 저장한다. 로그인 상태면 그 사용자 소유로 저장하고 동기화 대상에 넣는다. 비로그인이면 소유자 없음(guest)으로 저장하고 "로그인하면 기록이 계정에 저장되고 백업됩니다" 안내 후 로그인 선택 가능

### 정상 흐름 (계정, 기록)

1. 회원가입 또는 로그인 → 토큰과 사용자 id는 암호화 저장소에 저장
2. 로그인하면 로컬 DB의 guest 기록을 그 계정 소유로 바꾸고 동기화 대상에 넣는다.
3. 기록 화면은 로컬 DB만 읽어 현재 사용자 기록의 날짜별 세션 목록 → 세션 상세를 보여 준다(서버 조회는 2차, F-18).
4. 프로필 화면에서 신체 정보와 체형 수정 → 루틴 목표값에 반영
5. 로그아웃해도 로컬 기록은 지우지 않는다. 다른 계정으로 로그인하면 이전 계정의 기록은 보이지 않고 동기화되지도 않는다.

### 자동 동기화

- 실행 시점: 앱 시작 직후(특정 화면을 열지 않아도), 로그인 직후, 네트워크 복구 시, 운동 기록 저장 시
- 대상: 현재 로그인 사용자 소유이고 상태가 `pending`인 기록만. 비로그인 상태에서는 동기화하지 않는다.
- 응답별 처리:

| 결과 | 처리 | 기록 상태 |
|---|---|---|
| 201, 409(중복 client_id) | 저장 성공으로 처리 | `synced` |
| 네트워크 오류 | 이번 회차 즉시 중단, 다음 회차에 다시 시도 | `pending` 유지 |
| 5xx | 그 기록만 건너뛰고 다음 기록 진행, 시도 횟수 1 증가 | 5회 미만이면 `pending`, 5회 도달 시 `failed`(자동 재시도 중단) |
| 400, 403, 404, 413, 422 등 재시도 불가 4xx | 거절, Sentry 보고 | `rejected`(자동 재시도 안 함) |
| 401 | refresh 갱신 시도, 실패하면 이번 회차 중단하고 로그인 필요 상태로 표시 | `pending` 유지 |
| 429 | 이번 회차 중단, 다음 회차에 다시 시도 | `pending` 유지 |

- 기록 화면에서 `failed` 기록은 수동 재시도할 수 있다. 수동 재시도는 시도 횟수를 0으로 되돌리고 `pending`으로 바꾼 뒤 즉시 동기화한다.

### 예외 흐름

- 카메라 권한 거부: 권한이 필요한 이유와 설정 열기 버튼 표시, 운동 시작 불가
- 사람이 안 보일 때(운동 중): 2초 이상 미검출 시 일시정지, "카메라 앞에 서 주세요" 음성 안내, 다시 잡히면 자동 재개
- 사람이 안 보일 때(휴식 중): 일시정지하지 않고 휴식 타이머는 계속 간다.
- 여러 사람이 잡힐 때: 화면 중앙에 가장 크게 잡힌 1명만 추적
- 정면으로 섰을 때: 어깨 너비 대비 몸통 각도로 정면 판단 시 "옆으로 서 주세요" 안내
- 운동 자세가 아닐 때: 자세 게이트(7장)를 벗어난 프레임은 횟수 판정에 쓰지 않는다.
- 추론이 느릴 때(저사양): 추론 프레임을 건너뛰고, 10초 평균 10fps 미만이면 lite 모델로 전환. 백그라운드 복귀와 일시정지 해제 직후에는 성능 측정을 초기화해 멈춰 있던 시간이 평균에 들어가지 않게 한다.
- 네트워크가 끊겼을 때: 기록을 로컬에 저장하고 "나중에 자동으로 동기화됩니다" 표시, 연결 복구 시 재시도
- 동기화 오류: 위 "자동 동기화" 표를 따른다.
- 토큰 만료: refresh로 갱신 시도. 실패했을 때
  - 운동 세션 중(촬영 가이드, 운동, 휴식): 화면을 옮기지 않고 운동을 계속한다. 결과 화면에서 저장, 동기화할 때 "로그인이 필요합니다" 안내(needLogin 흐름)를 보여 주고, 기록은 로컬에 그대로 남는다.
  - 운동 세션 밖의 화면: 로그인 화면으로 이동
- 운동 중 앱이 백그라운드로 갈 때: 세션 일시정지, 복귀 시 "이어서 할까요?" 확인
- 운동 화면에서 Android 뒤로 가기: 종료 확인 창 표시. "종료"를 누르면 그때까지의 기록으로 결과 화면, "취소"를 누르면 그대로 계속
- 한국어 TTS 음성이 없는 기기: 음성 대신 글자 안내만 하고, "이 기기에서는 음성 안내를 쓸 수 없어 글자로 안내합니다"를 한 번 알린다.
- 입력이 비었을 때(가입, 로그인, 프로필): 필드별 오류 문구 표시, 요청 보내지 않음

## 5. 화면 목록

모든 화면은 세로 고정이다(푸쉬업 포함).

| 화면 | 경로 | 주요 요소 | 관련 기능 ID |
|---|---|---|---|
| 홈 | `/` | 운동 선택 카드, 오늘 기록 요약(로컬 DB), 로그인 상태 | F-09, F-12 |
| 촬영 가이드 | `/workout/:type/setup` | 카메라 미리보기(실제 비율), 실루엣 가이드, 운동별 안내 문구와 거리 안내, 전신 인식 상태, 3·2·1 카운트다운 | F-01, F-06, F-07 |
| 운동 | `/workout/:type` | 카메라, 스켈레톤, 횟수, 세트, 점수, 오류 문구, 일시정지/종료, 뒤로 가기 종료 확인 창 | F-01~F-08 |
| 휴식 | 운동 화면 위 오버레이 | 카운트다운, 다음 세트 정보, 건너뛰기 | F-08 |
| 운동 결과 | `/workout/result` | 총 횟수, 평균 점수, 반복별 점수 그래프, 자주 나온 오류, 로그인 필요 안내(비로그인, 토큰 만료 시) | F-05, F-10, F-11 |
| 로그인 | `/login` | 이메일, 비밀번호, 회원가입 이동 | F-10 |

## 6. API 목록

기존 Django 백엔드를 정리해 쓰는 것을 전제로 한 초안이다. 백엔드 코드 확인 후 확정한다(열린 질문 Q-01).
1차 범위에서 서버는 기록 백업 용도로만 쓴다. 앱은 기록을 서버에서 읽지 않는다.

| 메서드 | 경로 | 요청 | 응답 | 에러 |
|---|---|---|---|---|
| POST | `/api/auth/signup/` | email, password, nickname | 201, user | 400 중복 이메일, 형식 오류 |
| POST | `/api/auth/login/` | email, password | access, refresh, user(id 포함) | 401 |
| POST | `/api/auth/refresh/` | refresh | access | 401 |
| GET | `/api/users/me/` | (인증) | user, profile | 401 |
| PATCH | `/api/users/me/` | nickname, height_cm, weight_kg, body_shape | user, profile | 400, 401 |
| POST | `/api/workouts/` | 세션 전체(client_id 포함) | 201, 세션 | 400, 401, 403, 404, 409 중복 client_id(성공으로 처리), 413, 422, 429, 5xx. 앱 처리는 4장 "자동 동기화" 표 |

2차 범위(F-18):

| 메서드 | 경로 | 요청 | 응답 | 에러 |
|---|---|---|---|---|
| GET | `/api/workouts/?from=&to=` | (인증) | 세션 목록(요약) | 401 |
| GET | `/api/workouts/:id/` | (인증) | 세션 상세(세트, 반복) | 401, 404 |

- 실시간 프레임 분석 API(`exercise/{type}/`)는 없앤다.
- 세션 업로드는 `client_id`(앱이 만든 UUID)로 중복 저장을 막는다. 409는 앱에서 "이미 저장됨"으로 처리한다.

### 로컬 기록 소유 규칙

- 기기 암호화 저장소에 토큰과 함께 현재 사용자 id를 저장한다.
- 조회(기록 목록, 상세, 홈 요약)와 동기화는 현재 사용자 id 소유 기록만 대상으로 한다.
- 비로그인 상태에서 만든 기록은 user_id null(guest)로 저장하고, 비로그인 상태의 기록 화면에는 guest 기록만 보인다.
- 로그인하면 guest 기록 전부를 그 사용자 id로 바꾸고 `pending`으로 동기화 대상에 넣는다.
- 로그아웃해도 기록은 지우지 않으며, 다른 계정으로 로그인하면 이전 계정 기록은 조회되지도 동기화되지도 않는다.

### 횟수 판정 기준 (초기값)

판정에는 "반복을 시도했는가"(횟수)와 "충분히 깊었는가"(품질) 두 질문이 있다. 횟수 기준(120도)은 깊이 기준(90도)보다 반드시 얕아야 하며, 그래야 깊이 부족 오류가 나올 수 있다.

| 구간 | 기준 (푸쉬업 팔꿈치, 스쿼트 무릎 공통) | 횟수 | 결과 |
|---|---|---|---|
| 준비 자세 (UP) | 160도 이상 | - | - |
| 부분 반복 | 145도 미만으로 내려갔다가 120도 이하에 닿지 못하고 다시 160도 이상 | 세지 않음 | `PARTIAL` 사건 발생, "더 내려가세요" 음성, 점수 없음 |
| 얕은 반복 | DOWN(120도 이하) 도달, 최저 각도 91~120도 | 셈 | 깊이 부족 오류 기록, 감점 |
| 정상 반복 | DOWN 도달, 최저 각도 90도 이하 | 셈 | 깊이 감점 없음 |

| 운동 | 기준 관절 | UP | 하강 시작 | DOWN(횟수 인정) | 깊이 기준 | 최소 1회 시간 |
|---|---|---|---|---|---|---|
| 푸쉬업 | 팔꿈치 | 160도 이상 | 145도 미만 | 120도 이하 | 90도 이하 | 0.6초 |
| 스쿼트 | 무릎 | 160도 이상 | 145도 미만 | 120도 이하 | 90도 이하 | 0.8초 |

- 상태 전이(UP, 하강, DOWN)는 이동 평균 각도로 판정한다. 이동 평균 창은 프레임 수가 아니라 시간 기준(최근 약 150ms, 최소 1프레임)으로 해 fps에 덜 민감하게 한다.
- UP → DOWN → UP 순서가 완성될 때만 1회로 센다. DOWN에 닿은 뒤 120~160도 사이에서는 상태를 유지한다.
- UP과 DOWN 사이를 40도로 둔 이유: MediaPipe 각도는 프레임마다 5~10도 흔들리므로 가만히 있을 때 횟수가 잘못 올라가지 않게 한다. 145도도 같은 이유로 흔들림(약 15도)과 실제 하강을 구분하는 선이다.
- 처음 UP에 도달하기 전의 움직임은 세지 않는다. 다음 세트 시작과 일시정지 재개 때 분석기 상태를 초기화하고 이 규칙을 다시 적용한다.
- 휴식과 일시정지 중에는 분석기에 프레임을 넣지 않는다.

### 깊이 판정

- 반복의 최저 각도(깊이 판정, `PU_SHALLOW`, `SQ_SHALLOW`, RepRecord.min_angle)는 이동 평균이 아니라 원시 각도로 계산한다.
- 원시 각도가 가장 낮은 프레임과 그 앞뒤 프레임, 모두 3프레임의 중앙값을 최저 각도로 쓴다(튀는 값 1개 제거).

### 측정 쪽 유지 규칙

- 측정 쪽(좌/우)은 세트 시작 때 신뢰도가 높은 쪽으로 정한다.
- 세트 중에는 선택된 쪽의 신뢰도가 기준 아래로 떨어진 상태가 0.5초 이상 이어질 때만 반대쪽으로 바꾼다. 짧게 흔들리는 것으로는 바꾸지 않는다.

### 시간 기준

- 세션 시간(세트, 휴식 카운트다운, 일시정지, 운동 시간, started_at, ended_at)은 앱 시계 하나로 잰다.
- 프레임 타임스탬프는 판정 분석(이동 평균 창, 최소 1회 시간, duration_ms, 측정 쪽 유지 시간)에서만 쓴다.

### 반복 점수 계산 (초기값)

- 100점에서 시작해 오류 코드마다 감점: 깊이 부족 -25, 허리 처짐 -30, 엉덩이 들림 -20, 상체 숙임 -20, 뒤꿈치 들림 -15
- 1회 시간이 3초를 넘으면 -5(템포 저하), 0점 아래로 내려가지 않음
- 부분 반복은 점수를 매기지 않고 세트 평균에도 넣지 않는다. 대신 세션 결과에 부분 반복 횟수를 따로 표시한다.

## 8. 비기능 요구사항

- 플랫폼: Android 8.0(API 26) 이상, 모든 화면 세로 고정(푸쉬업 포함). iOS는 범위 밖.
- 기술 구성: Flutter, Riverpod, go_router, MediaPipe Tasks(Kotlin 플랫폼 채널), flutter_tts, drift(로컬 DB), flutter_secure_storage, dio
- 운동 세션 동안 화면 꺼짐 방지(세션 종료 시 해제)
- 보안:
  - 카메라 영상은 저장하거나 전송하지 않는다. 랜드마크도 개발자 메뉴의 명시적 내보내기 외에는 기기 밖으로 보내지 않는다.
  - 토큰과 사용자 id는 암호화 저장소에만 저장한다.
  - 로컬 기록은 소유자별로 구분하며, 다른 계정의 기록을 조회하거나 동기화하지 않는다.
  - 서버 주소, Sentry DSN 같은 설정은 `--dart-define`이나 `.env`로 분리하고 Git에는 예시 파일만 올린다.
  - 포즈 모델 파일은 저장소에 넣지 않는다. 다운로드 스크립트로 받고 체크섬이 맞지 않으면 빌드를 멈춘다.
  - 릴리스 빌드는 HTTPS만 허용한다.
  - 결제 정보는 앱에서 다루지 않는다.
- 성능:
  - 중급 기기 기준 추론 20fps 이상, 카메라 미리보기는 원본 프레임레이트 유지
  - 촬영 가이드에서 운동 화면으로 넘어갈 때 카메라를 멈추거나 다시 열지 않는다.
  - 음성 안내 지연은 판정 시점부터 0.5초 이내
  - 15분 연속 운동 시 앱이 강제 종료되지 않을 것
- 접근성: 모든 핵심 피드백(촬영 가이드 상태, 카운트다운, 횟수, 오류, 세트, 휴식과 휴식 종료 3초 전)은 음성으로도 제공한다. 한국어 음성이 없으면 글자로 대신하고 한 번 알린다. 점수는 색상만이 아니라 숫자로도 표시한다.
- 테스트 가능성: 자세 판정 로직(F-02~F-05, F-08)은 카메라 없이 녹화된 랜드마크 JSON으로 테스트할 수 있어야 한다. 세션 시계는 주입 가능해야 한다.
- 모니터링(Sentry 등): 앱은 sentry_flutter, 서버는 sentry-sdk. 추론 실패, 동기화 거절(rejected), 동기화 실패(failed), 비정상 종료를 보고한다. 개인 식별 정보는 보내지 않는다.
- 검증 도구(하네스 기본값의 Flutter 대응):

| 하네스 기본 | 이 프로젝트 |
|---|---|
| ESLint | `flutter analyze` + very_good_analysis 규칙 |
| Playwright | `integration_test` 또는 Patrol(권한 팝업 포함) |
| Sentry | sentry_flutter, sentry-sdk(Django) |
| 단위 테스트 | `flutter test`, 서버는 pytest |
| 사용자 최종 검증 | 로컬 Django(docker-compose) + 실기기 또는 에뮬레이터 |
