# Spec: Atheleo (Flutter Android 리팩토링)

- 상태: 초안
- 마지막 수정: 2026-11-09
- 근거 자료: 기존 저장소 `JJonyeok2/Atheleo`(React Native), Colab 노트북 "AI Model"(MoveNet, DTW 실험)

## 1. 목적

혼자 운동하는 사람이 휴대폰 카메라 하나로 푸쉬업, 스쿼트 횟수와 자세를 실시간으로 확인하고, 화면을 보지 않아도 음성으로 교정 안내를 받게 한다.
기존 앱은 매 프레임을 서버로 보내 분석해서 지연이 컸고, 화면 하나에 모든 로직이 몰려 유지보수가 어려웠다.
이번 리팩토링은 자세 추정을 기기 안으로 옮기고, 판정 로직을 테스트 가능한 단위로 분리하는 것이 핵심이다.

## 2. 사용자와 상황

| 사용자 | 상황 | 원하는 결과 |
|---|---|---|
| 홈트레이닝 초보자 | 거실에서 휴대폰을 세워 두고 운동 | 횟수를 대신 세 주고, 틀린 자세를 그 자리에서 알려 줌 |
| 운동 경험자 | 세트와 휴식 시간을 지켜 루틴 수행 | 목표 횟수, 세트, 휴식을 자동으로 관리 |
| 기록을 남기고 싶은 사용자 | 운동 후 결과 확인 | 날짜별 횟수, 점수, 자주 틀린 자세를 확인 |
| 개발자 본인 | 판정 모델 학습 데이터 수집 | 운동 중 랜드마크를 파일로 내보내기 |

| F-08 | 세트와 휴식 관리 | 목표 횟수 달성 시 세트 증가, 휴식 카운트다운, 다음 세트 안내 | 필수 |

| F-10 | 회원가입, 로그인 | JWT(access, refresh). 운동은 로그인 없이 가능, 기록 저장 시 로그인 요구 | 필수 |
| F-11 | 운동 기록 저장과 오프라인 동기화 | 로컬 DB에 먼저 저장 후 서버 동기화. 5xx와 네트워크 오류만 재시도 | 필수 |
| F-12 | 운동 기록 조회 | 날짜별 목록, 세션 상세(반복별 점수, 오류 빈도) | 필수 |
| F-13 | 프로필 | 닉네임, 키, 몸무게, 체형 조회와 수정 | 필수 |

| F-15 | 체형 분석 | 전신 사진으로 체형 분류, 기존 보정 로직 이식 | 2차 |
| F-16 | 학습 판정 모델 | 랜드마크 시퀀스 입력 자세 분류기(TFLite)로 F-04 대체 | 2차 |
| F-17 | 기준 동작 비교(DTW) | 기준 영상 각도 시퀀스와 비교 리포트 | 2차 |

## 4. 사용자 흐름

### 정상 흐름 (운동)

1. 앱 실행 → 홈에서 운동 종류(푸쉬업, 스쿼트) 선택
2. 카메라 권한 확인 → 촬영 가이드 화면("휴대폰을 옆에 세우고 측면으로 서 주세요", 전신이 보이는 실루엣 표시)
3. 전신이 2초 이상 안정적으로 잡히면 3초 카운트다운 후 시작
4. 반복할 때마다 횟수 음성 안내, 반복 종료 시 점수 표시와 섬광 색상
5. 자세 오류가 감지되면 해당 교정 문장 음성 안내(같은 문장은 5초 안에 다시 말하지 않음)
6. 목표 횟수 달성 → "세트 완료, N초 쉬세요" → 휴식 카운트다운 → "다음 세트를 시작하세요"
7. 마지막 세트 종료 또는 사용자가 종료 → 결과 화면(총 횟수, 평균 점수, 자주 나온 오류)
8. 로그인 상태면 기록 저장, 아니면 "로그인하면 기록이 저장됩니다" 안내 후 로그인 선택 가능

### 정상 흐름 (계정, 기록)

1. 회원가입 또는 로그인 → 토큰은 암호화 저장소에 저장
2. 기록 화면에서 날짜별 세션 목록 → 세션 상세
3. 프로필 화면에서 신체 정보와 체형 수정 → 루틴 목표값에 반영

### 예외 흐름

- 카메라 권한 거부: 권한이 필요한 이유와 설정 열기 버튼 표시, 운동 시작 불가
- 사람이 안 보일 때: 2초 이상 미검출 시 일시정지, "카메라 앞에 서 주세요" 음성 안내, 다시 잡히면 자동 재개
- 여러 사람이 잡힐 때: 화면 중앙에 가장 크게 잡힌 1명만 추적
- 정면으로 섰을 때: 어깨 너비 대비 몸통 각도로 정면 판단 시 "옆으로 서 주세요" 안내
- 추론이 느릴 때(저사양): 추론 프레임을 건너뛰고, 10초 평균 10fps 미만이면 lite 모델로 전환
- 네트워크가 끊겼을 때: 기록을 로컬에 저장하고 "나중에 자동으로 동기화됩니다" 표시, 연결 복구 시 재시도
- 서버가 400을 돌려줄 때: 해당 기록은 재시도 목록에서 제외하고 Sentry에 보고
- 토큰 만료: refresh로 갱신 시도, 실패하면 로그인 화면으로 이동(운동 중이면 세션 종료 후 이동)
- 운동 중 앱이 백그라운드로 갈 때: 세션 일시정지, 복귀 시 "이어서 할까요?" 확인
- 입력이 비었을 때(가입, 로그인, 프로필): 필드별 오류 문구 표시, 요청 보내지 않음

## 6. API 목록

기존 Django 백엔드를 정리해 쓰는 것을 전제로 한 초안이다. 백엔드 코드 확인 후 확정한다(열린 질문 Q-01).

| 메서드 | 경로 | 요청 | 응답 | 에러 |
|---|---|---|---|---|
| POST | `/api/auth/signup/` | email, password, nickname | 201, user | 400 중복 이메일, 형식 오류 |
| POST | `/api/auth/login/` | email, password | access, refresh, user | 401 |
| POST | `/api/auth/refresh/` | refresh | access | 401 |
| GET | `/api/users/me/` | (인증) | user, profile | 401 |
| PATCH | `/api/users/me/` | nickname, height_cm, weight_kg, body_shape | user, profile | 400, 401 |
| GET | `/api/workouts/?from=&to=` | (인증) | 세션 목록(요약) | 401 |
| GET | `/api/workouts/:id/` | (인증) | 세션 상세(세트, 반복) | 401, 404 |
| POST | `/api/workouts/` | 세션 전체(client_id 포함) | 201, 세션 | 400, 401, 409 중복 client_id(성공으로 처리) |

- 실시간 프레임 분석 API(`exercise/{type}/`)는 없앤다.
- 세션 업로드는 `client_id`(앱이 만든 UUID)로 중복 저장을 막는다. 409는 앱에서 "이미 저장됨"으로 처리한다.

### 횟수 판정 기준 (초기값)

| 운동 | 기준 관절 | UP | DOWN | 최소 1회 시간 |
|---|---|---|---|---|
| 푸쉬업 | 팔꿈치 | 160도 이상 | 100도 이하 | 0.6초 |
| 스쿼트 | 무릎 | 160도 이상 | 100도 이하 | 0.8초 |

- 각도는 최근 5프레임 이동 평균으로 계산한다.
- UP → DOWN → UP 순서가 완성될 때만 1회로 센다. 사이 구간에서는 상태를 유지한다.

### 반복 점수 계산 (초기값)

- 100점에서 시작해 오류 코드마다 감점: 깊이 부족 -25, 허리 처짐 -30, 상체 숙임 -20, 무릎 전진 -15
- 1회 시간이 3초를 넘으면 -5(템포 저하), 0점 아래로 내려가지 않음

## 8. 비기능 요구사항

- 플랫폼: Android 8.0(API 26) 이상, 세로 화면 고정. iOS는 범위 밖.
- 기술 구성: Flutter, Riverpod, go_router, MediaPipe Tasks(Kotlin 플랫폼 채널), flutter_tts, drift(로컬 DB), flutter_secure_storage, dio
- 보안:
  - 카메라 영상은 저장하거나 전송하지 않는다. 랜드마크도 개발자 메뉴의 명시적 내보내기 외에는 기기 밖으로 보내지 않는다.
  - 토큰은 암호화 저장소에만 저장한다.
  - 서버 주소, Sentry DSN 같은 설정은 `--dart-define`이나 `.env`로 분리하고 Git에는 예시 파일만 올린다.
  - 릴리스 빌드는 HTTPS만 허용한다.
  - 결제 정보는 앱에서 다루지 않는다.
- 성능:
  - 중급 기기 기준 추론 20fps 이상, 카메라 미리보기는 원본 프레임레이트 유지
  - 음성 안내 지연은 판정 시점부터 0.5초 이내
  - 15분 연속 운동 시 앱이 강제 종료되지 않을 것
- 접근성: 모든 핵심 피드백(횟수, 오류, 세트, 휴식)은 음성으로도 제공한다. 점수는 색상만이 아니라 숫자로도 표시한다.
- 테스트 가능성: 자세 판정 로직(F-02~F-05, F-08)은 카메라 없이 녹화된 랜드마크 JSON으로 테스트할 수 있어야 한다.
- 모니터링(Sentry 등): 앱은 sentry_flutter, 서버는 sentry-sdk. 추론 실패, 동기화 400, 비정상 종료를 보고한다. 개인 식별 정보는 보내지 않는다.
- 검증 도구(하네스 기본값의 Flutter 대응):

| 하네스 기본 | 이 프로젝트 |
|---|---|
| ESLint | `flutter analyze` + very_good_analysis 규칙 |
| Playwright | `integration_test` 또는 Patrol(권한 팝업 포함) |
| Sentry | sentry_flutter, sentry-sdk(Django) |
| 단위 테스트 | `flutter test`, 서버는 pytest |
| 사용자 최종 검증 | 로컬 Django(docker-compose) + 실기기 또는 에뮬레이터 |
