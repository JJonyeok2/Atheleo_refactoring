### Impl이 직접 정한 동작 평가
- 처음 결정: `_side ??= selectSide(frame)?.side`. 스쿼트에서 게이트에 걸린 프레임에서도 측정 쪽은 정해짐(테스트 고정). Task 규칙("처음 selectSide가 null이 아닌 프레임")과 일치.
- 떨어진 시간 계산: 첫 정상 아님 프레임 시각부터 현재 프레임 시각까지. 프레임이 끊겨도 다음 프레임에서 바로 전환됨. 끊긴 동안 상태를 알 수 없으므로 "떨어진 상태가 이어짐"으로 보는 것은 합리적이고 테스트로 고정됨. 문제 없음.
- 전환 시 미초기화: `MovingAverage`는 시간 창(기본 150ms)이고, 전환은 마지막 정상 프레임 뒤 최소 500ms가 지나서 일어나므로 전환 프레임에서 이전 쪽 값은 이미 창에서 빠짐. 기본값에서는 좌우 값이 이동 평균에 섞이지 않아 섞임으로 인한 가짜 상태 전이는 없음. 단 `sideSwitchAfterMs`를 창보다 작게 주면 섞일 수 있음(푸터에 기록). RepCounter에서 좌우 각도 차이가 임계값을 넘나들면 전이가 생길 수는 있으나 이는 섞임이 아니라 측정 값 자체의 계단이며, 미초기화는 Task 규칙이 정한 것.
- 전환 직후 반대쪽 각도도 못 쓰면(`selectSide`는 골랐으나 기준 각도 0/NaN) 측정 쪽은 바뀌고 그 시각부터 다시 떨어진 시간을 셈. 드문 경우이고 동작이 일관적이라 허용.
- 보관 프레임: UP이면 1개, unknown(시작 전, 취소 뒤)이면 비움, 하강 시작 프레임은 UP 프레임 뒤에 이어 붙음. 반복 출력 뒤 끝 프레임(UP 복귀)이 다음 반복의 하강 직전 프레임이 됨. 추가 발췌와 일치. `judgeRep`은 startMs 필터에 기대지 않고 프레임 목록 전체와 bottomMs만 쓰므로 범위 변경이 안전함.
- 게이트의 발목 NaN: 측정 쪽 각도는 정상이라 떨어진 시각을 지우고 게이트만 실패. 측정 쪽이 계속 바뀌지 않으므로, 측정 쪽 발목만 계속 못 쓰고 반대쪽은 멀쩡한 경우 푸쉬업이 세어지지 않는 한계가 있음. Task 규칙(정상 판정은 visibility와 기준 각도만)을 그대로 따른 결과라 허용, 푸터에 기록.
- 스쿼트 게이트의 취소(TASK-56) 뒤 재적용: `_counter.phase != RepPhase.unknown` 한 줄로 자연히 적용되고, RepCounter가 취소 뒤 unknown으로 가는 것은 TASK-56 테스트가 고정함. 분석기 수준 테스트는 없음(권장 사항).
