### Impl이 정한 동작 평가
1. 시각 역행 건너뜀(같은 시각은 받음), reset 시 기준 시각 초기화: 타당. reset 뒤 시각이 0부터 다시 와도 됨(TASK-52 재개와 맞음).
2. 보관 프레임을 하강/DOWN일 때만 쌓음: Task 계약("그 반복 구간(startMs~endMs) 프레임으로 judgeRep")과 일치. 단 judgeRep(TASK-09)의 "시작 자세 = repFrames 첫 프레임"이 하강 시작(이동 평균 145도 미만) 프레임이 됨. 아래 결정 필요 1 참고.
3. `lastAngle` = 마지막 이동 평균 각도, 쓸 수 있는 프레임 전엔 null, reset 시 null: 계약대로.
4. 비유한 기준 각도 건너뜀: 추가 발췌(TASK-07 QA 반영)대로.
- addFrame 처리 순서: 역행 검사 → 각도 → 이동 평균 1회 → 보관 → RepCounter → 출력 변환 → 비움. UP 복귀 프레임(endMs)과 하강 시작 프레임(startMs)이 모두 판정 프레임에 들어감. 취소(`RepCancelledEvent`)는 출력 null, 보관 프레임 비움 확인.

### 변이 확인 (13건, 원본 복원 확인)
- 잡힘(6): 역행 검사 제거, RepCounter에 원시 각도 전달, rawAngle에 평균 각도 전달, lastAngle을 원시 각도로, reset에서 기준 시각 미초기화, TooFastRep 미출력.
- 살아남음(7): 같은 시각 거부(`<=`), UP 프레임도 보관, 사건 시 비움 조건 제거, 보관을 RepCounter 뒤로 이동(UP 복귀 프레임 제외), 범위 필터 제거, isFinite 검사 제거, 건너뛴 프레임도 기준 시각 갱신. 이 중 3건(사건 시 비움, 범위 필터, isFinite)은 동작이 같은 변이. 나머지 4건은 판정 프레임 범위와 경계 처리라 현재 테스트로 고정되지 않음(권고 3).

## 오케스트레이터 결정 필요 (Impl 회귀 아님)
1. **judgeRep 시작 자세 범위 (Task 단계)**: Task 계약은 startMs~endMs 프레임을 넘기라고 했고 Impl은 그대로 함. 그 결과 스쿼트 뒤꿈치 기준(TASK-09 "repFrames 첫 프레임")이 하강 시작(이동 평균 145도, 원시 각도는 더 굽은 상태) 프레임이 되어, 뒤꿈치가 서서히 뜨는 동작은 기준값 0.1이 사실상 높아진 것처럼 판정됨. 실제 뒤꿈치 들림은 깊은 구간에서 주로 생겨 영향은 제한적이지만 판정이 달라지는 것은 실험으로 확인됨. 바꾸려면 Task 계약을 "직전 UP 프레임 1장(또는 하강 직전 프레임)부터 endMs까지"로 고치고 테스트(점진적 뒤꿈치 상승 스쿼트 클립 → sqHeelLift)를 함께 추가할 것. 유지하려면 TASK-09 "시작 자세" 정의에 "하강 시작 프레임"임을 명시할 것. 푸쉬업 몸통선 중앙값은 범위 영향이 작음.
2. **반복 시간 측정과 스쿼트 최소 1회 시간 (Spec 보정 후보)**: durationMs는 RepCounter 계약(TASK-08/56)대로 하강 시작~UP 복귀(이동 평균 기준)라 실제 동작 시간보다 약 25% 짧음. 의도된 측정 정의이며 Task 테스트 표에 스쿼트 시간 행은 없으므로 Impl이 추가 테스트 클립을 1.5초로 둔 것은 인수 조건을 가린 것이 아님. 다만 1초 스쿼트(733ms)는 빠른 반복이 되고, 1초 푸쉬업도 약 733ms로 기준 600ms와 여유 약 130ms. Spec의 "최소 1회 시간"이 실제 동작 시간을 뜻했다면 측정 정의 또는 squat 800ms 값을 실측(Q-05)과 함께 보정할 것.
